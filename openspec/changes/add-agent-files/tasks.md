# Tasks

## 1. The engine client

- [ ] 1.1 Give `ExecSpec` in `src/runtime/docker.ts` an optional `input: Buffer`. Start every exec on an upgraded connection (`Connection: Upgrade`, `Upgrade: tcp`, read from the `upgrade` event's socket), attach stdin only when there's input, and write the input once upgraded. Keep the bound, the abort and the error statuses as they are. Verify with `docker.test.ts` against its stub socket, taught to upgrade: an exec with input sends `AttachStdin: true` and the input reaches the socket; one without sends `AttachStdin: false`; frames still decode, the bound and the abort still close the stream, and a `404` or `409` still throws a `DockerError`.

## 2. Moving files in the runtime

- [ ] 2.1 Write the read and write scripts in `src/runtime/runtime.ts`, sent with each exec as `bash -c` with the path and size as arguments, never spliced in. The read script prints `ok <size>` then exactly those bytes, `missing`, `large <size>` past 16 MiB, or `error <message>`. The write script resolves the path through symlinks, creates its folders, refuses a folder, reads the declared size from stdin into `.<name>.jen-<random>` beside the target, deletes it and reports an error if it's short, keeps an existing target's mode, renames it over the target, and prints `ok` or `error <message>`. Each error carries the failing tool's own message. Verify with `runtime.test.ts` that the exec's command carries the path and size as arguments.
- [ ] 2.2 Add `readFile(caller, path, signal)` and `writeFile(caller, path, bytes, signal)` to `Runtime`, refusing as `runCommand` does: `404` for the owner, `403` without `workspace`, `409` when the workspace isn't running or stops during the call, told as `runCommand` tells it (factor out what they share). Bound each exec's read at 16 MiB plus 64 KiB, answer `502` to content longer or shorter than reported or a status line that doesn't parse, and abort and answer `502` past 30 seconds. Map `missing` to `404`, `large` to `413`, and `error` to `400` with its message. Verify with `runtime.test.ts` against `fake-docker.ts` for each status line, a stream longer and shorter than reported, a stream that never ends (with fake timers), a stopped workspace, and both refusals.
- [ ] 2.3 Add `GET` and `PUT /workspace/files?path=<path>` to `src/runtime/server.ts`: read the raw body for `PUT` up to 16 MiB (refusing a larger declared length unread, as `readBody` does), refuse a missing, empty, NUL-holding or over-4-KiB path with `400`, answer `GET` with `200` and `application/octet-stream`, and `PUT` with `204`. A caller that hangs up aborts the call, as for commands. Update the file's header comment. Verify with `server.test.ts` for each refusal, a binary body passing through unchanged both ways, and the `413` on a declared 17 MiB body.
