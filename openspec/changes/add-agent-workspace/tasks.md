## 5. Running a command

- [ ] 5.1 Write the wrapper script in the runtime's code, sent with each exec as `bash -c`: print its own PID and the process group it will run the command in as the first line, run the command with `bash -c` in that new group with stdout and stderr to `~/.jen/output/<id>.log`, then print the exit code and the file's size, then the file whole if it's within 8 KiB or else its first 2 KiB and last 6 KiB, and delete the file when nothing was cut. Verify with `runtime.test.ts` that the exec's command carries the user's command unchanged as an argument, not spliced into the script.
- [ ] 5.2 Add `runCommand(caller, command, timeout, signal)` to the runtime: refuse an owner (`404`) and an agent without `workspace` (`403`), check the caller's token again before the exec, run outside the tree queue, read at most 16 KiB, answer once the report parses, then close the stream. Past the bound, close the stream, kill the process group with a second exec and answer `502`. At the timeout, kill the process group, wait up to 5 seconds for the report, then kill the wrapper too and answer with `timedOut` true, `exitCode` null and no output. On the caller hanging up, kill the process group. A stream that ends without a report gets `409` if the workspace container isn't running, else `502`. Verify with `runtime.test.ts` cases for each against the fake engine, including a forged report after the first line and a stream that never ends, with fake timers for the deadline.
- [ ] 5.3 Serve `POST /workspace/commands` in `src/runtime/server.ts` with a 64 KiB body bound of its own (stop reading past it, `413` with `Connection: close`), `400` for a body that isn't JSON, a non-string `command` or a `timeout` outside 1 to 600, a default of 120 seconds, extra fields ignored, and the answer `{exitCode, output, timedOut, cut?}`. Abort the runtime's signal on the response's `close` when the response hasn't finished, as the relay does, not on the request's `close`, which fires once the body is read; a hang-up while the body is still arriving runs nothing. Verify with `server.test.ts` cases for each refusal, the default timeout, a connected client awaiting a delayed command without the call being aborted, and a client disconnecting while it waits aborting it.
- [ ] 5.4 Add one sentence on `POST /workspace/commands` to `record/environment.md`'s runtime API paragraph. Verify it matches the spec.
